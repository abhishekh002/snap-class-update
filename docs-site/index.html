Product and engineering guide

How SnapClass works

A practical map of the classroom app: its Streamlit runtime, biometric attendance flows, Gemini-powered learning tools, data model, and the decision math behind attendance forecasting.

Python + StreamlitSupabaseFace + voice matchingGemini AISource reviewed: Nov 2026

What the system does

Teachers manage classes, enroll students, review attendance, share learning material, and assess work. Students sign in, view class resources, and use study tools.

Attendance suggestions come from comparing a live capture with previously enrolled biometric templates. A teacher reviews the result before it is saved.

How to read this guide

Each section explains the implementation as it exists in the repository. Diagrams are supplied project assets. Thresholds and scores below are code rules, not claims of measured accuracy.

The repository does not train a custom neural network. It uses pretrained face and voice encoders and a nearest-match decision rule.
01 / Runtime

System architecture

One Python app coordinates UI, services, and storage.

The Streamlit process calls Supabase and external model/email APIs. The inspected code does not define a separate REST backend.

Request lifecycle

Main layers

  • Presentation: Streamlit screens in app.py and component modules.
  • Application logic: attendance, account, study, and assessment flows.
  • Persistence: Supabase database and storage buckets.
  • External services: dlib/face_recognition, Resemblyzer, Gemini, Abstract email reputation, and Resend.

Models and decision components

Pretrained encoders plus app-level rules.

Gemini models

Gemini Flash Lite supports board digitization and short explanations. An ADK agent powers the in-app assistant.

prompted generationno vector index found

What “training” means here

The code does not fine-tune these models. Enrolling a student stores a face or voice reference vector. The attendance path loads the gallery and matches new observations against it. The model cache refresh function reloads gallery data; it is not model training.

A matching threshold is a product decision. It needs evaluation on consented, representative classroom data before it can be treated as reliable for a particular school.
03 / Attendance

Face and voice pipelines

Capture → preprocess → compare → teacher review.

Face capture multi-angle flow

Each selected capture is processed separately. Recognized student IDs are merged across captures, then the teacher reviews the proposed attendance.

Face decision ambiguity handling

The teacher flow scopes candidates to the selected subject. The code rejects ambiguous matches when the best and next-best distances are too close (margin 0.05).

Voice check-in

Audio is decoded as mono 16 kHz, silence is trimmed, short segments are skipped, and accepted embeddings are compared with the stored voice reference.

Student and teacher journeys

The student login search spans student profiles, while teacher attendance matching is limited to enrolled students in the chosen subject. Teacher confirmation is an important safeguard.
04 / Generative AI

AI pipeline and learning tools

Model calls are task-specific and prompt-driven.

Board digitizer

Photo → Gemini Flash Lite → Markdown / LaTeX notes

Image bytes and an extraction prompt go to the model; generated notes are returned for review and saving.

Explain simply

Question → truncate input → short explanation

The ELI5 helper caps input at 6,000 characters and output at 500 tokens. Output should be treated as generated content.

Interactive reader

PDF, DOCX, PPTX, TXT, and Markdown are extracted into text. The preview is capped at 8,000 characters; the selected note context is sent with a question.

Quiz and study buddy

The quiz helper asks for three MCQs as JSON; a parse failure returns an empty list. Study buddy uses enrolled peers and prompts Gemini for a paired challenge. A repository search found no quiz-helper call site.

Retrieval limits

No embedding database, vector search, or persistent retrieval index was found. These features use text or files selected by the app at request time. Model answers can omit or invent details, so teachers should review generated material before publishing it.

06 / Mathematics

Decision math and formulas

Exact calculations reflected in the code paths.

Face matching uses nearest descriptor

Given a new 128D face vector e and an enrolled vector g, the code uses Euclidean distance. Smaller values mean the descriptors are closer.

d(e, g) = √( Σᵢ₌₁¹²⁸ (eᵢ - gᵢ)² )
Accept nearest match
d₁ < 0.60
Reject ambiguous pair
d₂ - d₁ < 0.05

Here d₁ is the smallest candidate distance and d₂ the second smallest. This score is not a probability or an accuracy measurement.

Voice score

The pipeline compares embeddings using a dot product (similarity score):

s(u, v) = Σᵢ uᵢvᵢ
accept when s ≥ 0.65

The inspected code does not explicitly normalize vectors or calibrate this cutoff against a labeled validation set. Interpret it as the implementation's score, not a percent confidence.

Attendance projections

Let A be attended sessions, T total sessions, and x future sessions attended.

current % = 100 × A / T
projected % = 100 × (A + x) / (T + x)

How many classes to reach 75%?

Assume the student attends every upcoming session. Solve the target inequality:

(A + x) / (T + x) ≥ 0.75
A + x ≥ 0.75T + 0.75x
0.25x ≥ 0.75T - A
x ≥ 3T - 4A

The app clamps negative answers to zero and uses integer class counts: max(0, 3T - 4A)

07 / Trust

Security, privacy, and operational limits

Design constraints that matter in deployment.

Account and email

  • Password hashes use bcrypt.
  • Password reset codes are six digits, expire after 10 minutes, and allow up to five incorrect attempts.
  • Code digests are HMAC-SHA256 bound to teacher ID and email. Pending reset state is in the Streamlit session.
  • Resend production sender must be verified. Test sender delivery can be restricted to the account owner.

Trust boundaries

API keys, service role credentials, and reset secrets must stay server-side. Never place these in browser code or public static assets.

Privacy and assurance checklist

  • Define consent, retention, and deletion procedures for biometric templates, with access auditing and a documented legal basis appropriate to the school.
  • Validate database row-level security, privileged-key boundaries, HTTPS configuration, backups, and restore operations before production.
  • Measure false match and false non-match rates on consented, representative local data; review outcomes across lighting, pose, camera distance, and demographics.
  • Do not treat face distance or voice similarity as calibrated confidence.
  • Set a dedicated random password_reset_secret (at least 32 characters) in production; the source has a fallback that is unsafe as a production configuration.
  • A Streamlit session reset can clear pending password reset state.
